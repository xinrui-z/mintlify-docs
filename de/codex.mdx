## 1. API-Key abrufen

Öffnen Sie die [Harogo-Konsole](https://console.harogo.ai/keys), erstellen Sie einen API-Key und kopieren Sie ihn. Behandeln Sie den Key wie ein Passwort. Committen oder teilen Sie ihn nicht. Wähle je nach gewünschter Abrechnung einen [Abo- oder Guthabenschlüssel](/de/pricing#billing-keys).

## 2. Harogo konfigurieren

Fügen Sie den Harogo-Provider zu Ihrer bestehenden `~/.codex/config.toml` hinzu. Behalten Sie vorhandene Provider und Profile. Ersetzen Sie nicht die ganze Datei.

```toml
[model_providers.harogo]
name = "harogo"
base_url = "https://api.harogo.ai/v1"
wire_api = "responses"

[profiles.harogo]
model = "gpt-6.2-sol"
model_provider = "harogo"
model_reasoning_effort = "high"
```

Setzen Sie `profile = "harogo"` nur, wenn Harogo das Standardprofil sein soll. Aktualisieren Sie in der bestehenden `~/.codex/auth.json` nur den Wert von `OPENAI_API_KEY` und behalten Sie alle anderen Einträge.

Mit [CC Switch](/de/troubleshooting#cc-switch) fügen Sie stattdessen denselben Provider dort hinzu und aktivieren ihn. Verwenden Sie nicht gleichzeitig mehrere Konfigurationen, wenn Sie ihre Priorität nicht kennen.

Prüfen Sie die [Tabelle zur Modellkompatibilität](/de#model-compatibility), bevor Sie eine Modell-ID auswählen.

## 3. Verbindung prüfen

Starten Sie den bereits installierten Client in Ihrem Projektverzeichnis:

```shellscript
codex
```

Senden Sie eine kurze Anfrage wie `Reply with exactly: 2`. Prüfen Sie die Antwort und das aktive Modell, zum Beispiel `gpt-6.2-sol`. Eine normale Antwort allein beweist nicht, dass Harogo aktiv ist.
