# Presentazione

Harogo è un abbonamento multi-modello pensato per gli agenti di coding.

Il prezzo scontato dell'abbonamento è di \$4.90 per il primo mese, poi \$9.90/mese, con 100 posti in abbonamento scontati attualmente disponibili. I posti rimanenti e il prezzo di liquidazione effettivo sono indicati nella pagina di abbonamento. L'abbonamento si rinnova automaticamente ogni mese e viene addebitato sulla tua carta tramite Stripe. Il prezzo del primo mese vale solo per il tuo primo abbonamento Harogo. Puoi annullare il rinnovo automatico in qualsiasi momento dalla pagina **Plan** della console e mantieni l'accesso fino alla fine del periodo già pagato.

Una volta abbonato, puoi usare più modelli di coding con un unico account Harogo e un'unica chiave API. Tutti i modelli condividono la stessa quota di abbonamento, quindi non serve registrarsi, ricaricare il saldo o gestire piattaforme di modelli separate.

# Perché Harogo

Modelli diversi eccellono in compiti di coding diversi. Usare direttamente più provider di modelli di solito significa gestire contemporaneamente più account, chiavi API, saldi, limiti di frequenza e fatture.

Harogo riunisce in un unico servizio una serie di modelli adatti agli agenti di coding. Puoi passare liberamente da un modello all'altro in base al task, e tutto viene conteggiato su un'unica quota di abbonamento condivisa.

I modelli attuali si dividono a grandi linee in questi gruppi:

- **Codebase estese e ragionamento complesso**: Kimi K3.1 Pro, Claude Opus 5.5, GPT-6.2 Sol, GPT-6.2 Astra
- **Coding quotidiano per agenti, generazione di codice e debug**: Qwen4 Max, GLM-5.3, Claude Sonnet 5.5, GPT-6.1 Terra, MiniMax M3, DeepSeek V4 Pro
- **Chiamate ad alta frequenza, risposte rapide e task sensibili ai costi**: DeepSeek V4.1 Flash 1017, Claude Haiku 5.5, GPT-6 Luna

Questi gruppi sono solo un riferimento per la scelta del modello. I risultati effettivi dipendono dal task, dal contesto e da come usi gli strumenti.

# Per iniziare

1. Accedi a Harogo e sottoscrivi l'abbonamento.
2. Crea e copia una chiave API nella console.
3. Usa `https://api.harogo.ai` per [Claude Code](/it/claude-code), oppure `https://api.harogo.ai/v1` per [Codex](/it/codex) e [OpenCode](/it/opencode). Segui la guida del tuo client.
4. Incolla la tua chiave API.
5. Inizia a usarlo.

Custodisci la tua chiave API. Non includerla nei commit di un repository pubblico e non condividerla con nessuno.

## Disponibilità dei modelli per client

Alcuni modelli sono limitati a un client specifico. Gli altri funzionano ovunque.

<Note>
**Modelli GPT** (GPT-6 Luna, GPT-6.2 Sol, GPT-6.2 Astra, GPT-6.1 Terra) sono disponibili solo in [Codex](/it/codex).

**Modelli Claude** (Claude Opus 5.5, Claude Sonnet 5.5, Claude Haiku 5.5) sono disponibili solo in [Claude Code](/it/claude-code).

**Tutti gli altri modelli** (GLM, Qwen, Kimi, MiniMax, DeepSeek) non hanno restrizioni di client e funzionano in qualsiasi client supportato.
</Note>

## Utilizzo e limiti

Harogo applica i seguenti limiti di utilizzo:

- Limite giornaliero: \$12
- Limite settimanale: \$30
- Limite mensile: \$60

Tutti e tre i limiti si applicano contemporaneamente. Ogni chiamata al modello attinge dalla quota di abbonamento condivisa. Ogni modello ha un proprio limite di utilizzo: i modelli con limite inferiore a \$60 consumano la quota condivisa più rapidamente, quelli con limite superiore a \$60 più lentamente. Il limite di ciascun modello è indicato in [Prezzi](/it/pricing).

I limiti sono definiti in dollari anziché in un numero fisso di richieste. Il numero di richieste che ottieni effettivamente dipende dal modello che usi: i modelli più economici in genere consentono più richieste, quelli più costosi meno.

Puoi verificare l'utilizzo attuale e la quota residua nella [console Harogo](https://console.harogo.ai/plan).

### Metodo di stima

Queste stime si basano sul seguente profilo di richiesta tipico:

- **GLM-5.3**: circa 700 token di input, 52,000 token di lettura dalla cache e 150 token di output per richiesta. (Riutilizza il profilo di richiesta di GLM-5.2.)
- **Qwen4 Max** — circa 8.731 token di input, 31.831 di lettura cache e 2.029 di output per richiesta. (Stima provvisoria.)
- **Kimi K3.1 Pro**: circa 1,050 token di input, 76,500 token di lettura dalla cache e 300 token di output per richiesta. (Riutilizza il profilo di richiesta di Kimi K3.)
- **MiniMax M3**: circa 4,381 token di input, 28,768 token di lettura dalla cache e 1,108 token di output per richiesta.
- **DeepSeek V4 Pro**: circa 750 token di input, 82,000 token di lettura dalla cache e 290 token di output per richiesta.
- **DeepSeek V4.1 Flash 1017**: circa 790 token di input, 68,000 token di lettura dalla cache e 280 token di output per richiesta. (Riutilizza il profilo di richiesta di DeepSeek V4 Flash 0731.)
- **Claude Opus 5.5**: circa 580 token di input, 386,230 token di lettura dalla cache, 19,476 token di scrittura nella cache e 2,025 token di output per richiesta. (Riutilizza il profilo di richiesta di Claude Opus 5.)
- **Claude Sonnet 5.5**: circa 159 token di input, 129,804 token di lettura dalla cache, 6,260 token di scrittura nella cache e 850 token di output per richiesta. (Usa il profilo di richieste osservato in una versione precedente del modello.)
- **Claude Haiku 5.5**: circa 700 token di input, 52,000 token di lettura dalla cache e 150 token di output per richiesta. (Riutilizza il profilo di richiesta di Claude Haiku 4.5.)
- **GPT-6 Luna**: circa 45,726 token di input, 10,720 token di lettura dalla cache e 1,905 token di output per richiesta. (Riutilizza il profilo di richiesta di GPT-5.6 Luna.)
- **GPT-6.2 Sol**: circa 6,032 token di input, 112,138 token di lettura dalla cache e 678 token di output per richiesta. (Riutilizza il profilo di richiesta di GPT-5.6 Sol.)
- **GPT-6.2 Astra**: circa 6,032 token di input, 112,138 token di lettura dalla cache e 678 token di output per richiesta. (Basato temporaneamente sul profilo di richiesta di GPT-5.6 Sol.)
- **GPT-6.1 Terra**: circa 6,825 token di input, 69,476 token di lettura dalla cache e 734 token di output per richiesta. (Riutilizza il profilo di richiesta di GPT-5.6 Terra.)

Per ora le nuove versioni dei modelli riutilizzano il profilo di richiesta osservato sul modello precedente. Richieste = quota della finestra ÷ (prezzo di listino per richiesta × 0.1) × (limite del modello ÷ \$60).

Questi dati servono a stimare un utilizzo tipico e non costituiscono un impegno su un numero fisso di richieste. I limiti quota e i volumi di richieste stimati possono cambiare con l'evoluzione del servizio: per le informazioni più aggiornate consulta la console Harogo e questa pagina.
